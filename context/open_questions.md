- [x] dynavlan C1 mechanism: Can `netplan try` be driven non-interactively from a script on a headless box (no TTY)? (resolved 2026-07-14 on the lab box) - YES, both paths work over SSH with no TTY: (1) unchanged config + no input -> counts down --timeout and reverts, exit 0; (2) feed newline to stdin -> "Configuration accepted.", exits immediately, no revert. So dynavlan's rollback = write 90-dynavlan.yaml -> `netplan try --timeout N` (applies then waits) -> health check (default route via base uplink present + reachability) -> feed "\n" to ACCEPT if healthy, else let timer REVERT. Timer also backstops script death mid-window. Impl detail for build: drive netplan try's stdin via a fifo/coproc so the accept can be sent after the health check.
- [x] dynavlan C4b: On igb NIC, does `rx-vlan-filter: on [fixed]` block sniffing of UNconfigured VLANs? (resolved 2026-07-14 on the lab box) - NO, promisc bypasses it. C4 fully closed on igb hardware: no ethtool -K needed (rx-vlan-offload already off = no stripping; filter bypassed by promisc). SURVIVING DESIGN REQ: dynavlan must `ip link set <iface> promisc on` before sniffing (promisc is what makes the filter transparent; at boot iface may not be in promisc before Domotz starts).

- [ ] dynavlan C4 (original): Do the Protectli Intel NICs strip 802.1Q tags via rx-vlan offload before tcpdump sees them? (resolved 2026-07-14) - NO on this igb box: rx-vlan-offload already off. Tag stripping is not the problem here; tag filtering (C4b above) is the real risk. - architect says likely yes on Intel, which would make passive sniff detect zero VLANs. Test order on real hardware: (1) FIRST check whether `tcpdump -e -nn` already shows "vlan N" with offload left ON - Linux libpcap reconstructs the outer tag from PACKET_AUXDATA even when HW strips it, so we may not need to touch offload at all. (2) ONLY if tags are invisible, fall back to `ethtool -K <iface> rxvlan off`. Caveats for the fallback: ethtool -K can bounce the Intel link (igb/e1000e/igc reinit), and that interface carries Domotz's own untagged uplink, so it would briefly disconnect Domotz; the setting is runtime-only (re-apply per boot); apply ONCE at boot with check-then-set (query `ethtool -k` first, skip if already off), NEVER on the 5-min rescan (would bounce the uplink every cycle).
